XSLT Bridge · guide

MSXML and ActiveXObject in Chrome and Edge

Many business apps written for Internet Explorer use ActiveXObject and MSXML to load XML and apply XSLT. ActiveXObject exists only in Internet Explorer, so those apps don't work in normal Chrome or Edge tabs. Many organizations keep them running in Edge's IE mode.

Your options

  • Stay in IE mode. The app keeps running on the old engine, and it stays tied to IE mode.
  • Rewrite the XML code. Replace the MSXML calls with standard browser APIs or server-side code. This is the long-term fix, and it takes development time.
  • Use a compatibility layer. The XSLT Bridge paid edition adds MSXML compatibility in normal tabs on the sites your IT team approves, including ActiveXObject, DOMDocument, selectNodes, transformNode and XSLTemplate.

Compatibility covers common patterns, and we can't promise it for every app, so test yours first. We can arrange a trial and a security review. XSLT Bridge sends nothing to us automatically: no telemetry, no analytics and no license server.

The free edition covers XSLT and XML rendering, not MSXML. See pricing.
