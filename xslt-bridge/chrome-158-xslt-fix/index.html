Chrome and Edge 158 remove XSLT: how to check and fix your apps

Chrome and Microsoft Edge remove built-in XSLT by default starting with version 158, which ships on November 17, 2026. Web pages and apps that use XSLT to turn XML into HTML can then show raw XML or errors.

What is affected

  • XML files and reports that point to a stylesheet, opened in a normal browser tab
  • Web apps that call the browser's XSLTProcessor API
  • CDISC define.xml files (see the define.xml guide)

Apps running in Edge's IE mode use the old Internet Explorer engine, so this change doesn't touch them.

Check in one minute

You can see the effect today, before your browser updates:

  1. Close every Chrome (or Edge) window. If one stays open, the setting is ignored.
  2. Press Windows + R and type chrome --disable-blink-features=XSLT (for Edge: msedge --disable-blink-features=XSLT).
  3. Open your apps and XML reports. If a page shows raw XML or an error, it will look like that after the update.

To go back, close the browser and open it normally.

Your options

  • Rewrite that part of the app. Do the XSLT step on the server, or move it to a JavaScript library. This is the long-term fix, and it takes development time.
  • Convert files ahead of time. For static reports, generate an HTML copy and open that instead.
  • Move the app to IE mode. This works if your organization already manages it, though it keeps the app tied to IE mode.
  • Use a browser extension. XSLT Bridge restores XSLT only on the sites and folders you or your IT team approve, and it sends nothing to us automatically. The free edition covers XSLT and XML rendering.
