Zinvera verify.py fingerprints

The script a firm or its auditor runs to check a Zinvera firm export, on their own machine, with nothing from Zinvera running.

NeedsPython 3.8 or newer, nothing else; it uses no network

Each export carries its own copy of verify.py and its method text, and the method text and every approval memo name the version of verify.py they came with and its SHA-256. Every version Zinvera has published stays listed under All versions with its hashes, so a memo from an earlier year, which names an earlier version, can still be matched: a memo's hash must be the one listed there for the version the memo names.

How to check it

  1. Take the copy of verify.py from the export and keep it in a folder of your own, outside the export. This page publishes only the fingerprints, so you can confirm that copy is genuine.
  2. Check its hash. Either of these prints it: 
    python -I -B verify.py --version
certutil -hashfile verify.py SHA256      (Windows)
shasum -a 256 verify.py                  (macOS, Linux)
    Find the version it prints under All versions: its SHA-256 must be the one listed for that version, and so must the hash the export's canonical-json-method.txt names. Then, for each memo, find the version the memo names: the memo's hash must be the one listed for that version. A memo naming an older version is expected; a hash that isn't listed for its version means stop and ask. Use the newest version to check an export.
  3. Unzip the export and run your copy on it, in Python's isolated mode: 
    python -I -B /your/copy/verify.py <unzipped export> --fingerprint <chain fingerprint from your newest memo> --anchors <your anchors folder>
    -I keeps Python from loading anything from the export or the folder you run it in, so a file such as hashlib.py put in the export can't stand in for part of Python. verify.py refuses to run without it, and checks that the modules it uses come from Python's own library.
  4. It prints its own version and SHA-256 first, one line for each check, notes to match against your workpapers, and ends with PASS, or FAIL with what failed. The export's canonical-json-method.txt says what each check proves, and what it can't.
